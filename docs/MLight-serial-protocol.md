## 1. 概览

MLight 状态灯是一块 USB CDC 虚拟串口设备（RP2040），
主机通过串口发送**ASCII 文本行**控制灯效：颜色 × 模式、总开关、亮度。

| 项目 | 值 |
| --- | --- |
| 传输方式 | USB CDC（虚拟串口） |
| 波特率 | 115200（CDC 下实际不影响速率，但两端都按此配置） |
| 帧格式 | 8 数据位 / 无校验 / 1 停止位（8N1）/ 无流控 |
| 编码 | ASCII |
| 行结束符 | `LF`（`\n`，**不是 CRLF**） |
| 通信方向 | **单向**：主机只写，不读取应答，无 ACK、无查询命令 |
| 命令校验 | 仅在主机侧做白名单校验；设备侧收到无法识别的行如何处理未确认 |

## 2. 命令语法

```
<COLOR>_<MODE>          # 单通道控制
OFF                     # 全部关闭
BRIGHTNESS_<0..100>     # 全局亮度
<CMD>+<CMD>[+<CMD>…]    # 组合命令（仅主机侧展开，见 §4）
```

- `COLOR`：`RED` / `YELLOW` / `GREEN`（大写，仅这三种）
- `MODE`：`ON` / `OFF` / `BLINK` / `BREATH`（大写）

主机侧校验正则（Windows 后台，逐条命令发送前校验）：

```regex
^(OFF|(RED|YELLOW|GREEN)_(ON|OFF|BLINK|BREATH)|BRIGHTNESS_(100|[1-9]?\d))$
```

注意：`+` 组合**不会整串下发**，主机拆成多条、逐条发送。

## 3. 命令表

| 命令 | 灯效 | 说明 |
| --- | --- | --- |
| `RED_ON` | 红常亮 | |
| `RED_OFF` | 关红 | 只关该颜色通道，不影响其他通道 |
| `RED_BLINK` | 红闪烁 | 闪烁节奏由固件决定 |
| `RED_BREATH` | 红呼吸 | 渐亮渐暗 |
| `YELLOW_ON` / `_OFF` / `_BLINK` / `_BREATH` | 黄灯同上 | |
| `GREEN_ON` / `_OFF` / `_BLINK` / `_BREATH` | 绿灯同上 | |
| `OFF` | 全部关闭 | 关闭所有通道 |
| `BRIGHTNESS_0` … `BRIGHTNESS_100` | 设置亮度 | 整数百分比，0 = 最暗，100 = 最亮 |

## 4. 组合命令与通道语义

### 4.1 `+` 组合

三灯珠机型可以在同一时刻点亮多个通道：

```
GREEN_ON+RED_ON           # 绿常亮 + 红常亮
GREEN_ON+RED_OFF          # 绿常亮 + 关红
GREEN_ON+YELLOW_BREATH    # 绿常亮 + 黄呼吸（"任务运行中"的标准灯效）
```

**顺序有意义**：设备把**最后一条模式命令**当作当前动画模式，因此
`GREEN_ON` 必须放在最前面，动画色放在最后。

### 4.2 单灯珠机型

`single-rgb-1003` 与 `series-ws2812-1007` 只有一个物理发光体（或一串同步灯珠），
此类机型同一时刻只能呈现一种颜色，组合命令只需保留**最后一条**：

```
GREEN_ON+YELLOW_BREATH  ──(单灯珠)──▶  YELLOW_BREATH
```

目的是避免 RGB 加色混光造成的串色（代码注释原文：*"Sending only that command
prevents additive RGB mixing and color bleed"*）。

## 5. 时序要求（实现时需照做）

| 场景 | 要求 | 原因 |
| --- | --- | --- |
| 状态切换前 | 先发 `OFF`，等待 **350 ms** 再发新命令 | 背靠背 `OFF`/`GREEN_ON` 会让控制器漏掉 `OFF`，旧呼吸动画可能继续跑 |
| 组合命令拆分 | 每条之间间隔 **300 ms** | 给控制器留处理时间，保证顺序生效 |
| `single-rgb-1003` 进入 `YELLOW_BREATH` | 先发 `YELLOW_ON`，等 **80 ms** 再发 `YELLOW_BREATH` | 呼吸周期起点接近最暗，避免"看起来没反应"。**仅 1003 单灯珠做这一步，1007 不做** |
| 相同命令重复下发 | 抑制，不重发 | 重发 `*_BREATH` 会重置动画相位，造成可见跳变 |
| 串口重连后 | 允许重放最后一条命令 | 恢复断电/重插前的灯效 |

## 6. 设备发现与串口参数

### 6.1 USB 标识

| 项 | 值 |
| --- | --- |
| VID | `0x2E8A`（Raspberry Pi） |
| PID | `0x0003` / `0x000A` → 状态灯 |
| 排除 | `PID 0x101F` —— 同厂商的 CPU/GPU 温度显示设备，**不是**状态灯 |
| 可选过滤 | USB 序列号（用于绑定具体设备、避免多灯互相抢占） |

> 状态灯与温度显示器共用 VID 和 CDC 接口，必须靠 PID + 序列号区分，
> 不能只按"VID_2E8A 的串口"挑设备。

### 6.2 设备型号（profile）

| profile | 含义 | 组合命令处理 |
| --- | --- | --- |
| `single-rgb-1003` | 单灯珠（LC-RGB） | 只发最后一条 |
| `standard-three-led` | 三灯珠 | 原样逐条发送，可多色并存 |
| `series-ws2812-1007` | 1007 三颗串联 | 三颗同步同色，只发最后一条 |

型号无法确认时不要假设 profile：单色与三灯珠对组合命令的处理不同，猜错会出现混色或只亮一颗。

### 6.3 串口参数

| 项 | 值 |
| --- | --- |
| 波特率 | **115200** |
| 帧格式 | 8 数据位 / 无校验 / 1 停止位（8N1）/ 无流控 |
| 行结束 | **LF**（`\n`），ASCII 文本 |
| 端口名 | Linux `/dev/ttyACM0`；macOS `/dev/cu.usb*`；Windows `COMx` |
| 说明 | CDC 虚拟串口，波特率不参与实际速率，但两侧仍按 115200 打开 |

### 6.4 设备就绪与重连

实测"插上立刻发命令"经常收不到，设备从枚举到可接收命令有一段准备时间：

| 阶段 | 建议做法 |
| --- | --- |
| 设备刚枚举 | 等待约 **0.8 s** 再打开串口 |
| 串口打开后 | 等待约 **1.2 s** 再发第一条命令（或补发最后一条，恢复断电前灯效） |
| 写失败/发送不完整 | 关闭串口重连，成功后才更新"当前灯效"缓存 |
| 同一命令重复下发 | 跳过，避免打断进行中的动画 |

> 这几段等待与"第一次插上不亮、重插才亮"的现象直接相关，移植到其他宿主时建议保留。

## 7. 手动控制示例

### 7.1 Linux / macOS

> 以下命令已在 Linux 下实测可用（`/dev/ttyACM0`，115200 8N1）。

```bash
PORT=/dev/ttyACM0          # macOS 通常为 /dev/cu.usbmodem*
stty -F "$PORT" 115200 raw -echo -hupcl

printf 'OFF\n'           > "$PORT"   # 清场
sleep 0.35
printf 'GREEN_ON\n'      > "$PORT"   # 连接正常
sleep 0.3
printf 'YELLOW_BREATH\n' > "$PORT"   # 任务运行
sleep 0.3
printf 'RED_BLINK\n'     > "$PORT"   # 需要确认
printf 'BRIGHTNESS_60\n' > "$PORT"   # 亮度 60%
```

### 7.2 Python（pyserial）

```python
import time
import serial

ser = serial.Serial('/dev/ttyACM0', 115200, timeout=0.5)  # Windows: 'COM3'

def send(cmd):
    ser.write((cmd + '\n').encode('ascii'))
    ser.flush()

send('OFF')
time.sleep(0.35)
send('GREEN_ON')
time.sleep(0.30)
send('YELLOW_BREATH')      # 单灯珠；三灯珠改成 GREEN_ON+YELLOW_BREATH 拆成两条
ser.close()
```

## 8. 已知限制

1. **协议只有 3 种颜色**：命令层面只有 `RED` / `YELLOW` / `GREEN`。
   产品宣传的"7 种颜色"对应 RGB 灯珠的物理混色能力（红、绿、蓝、黄、青、紫、白），
   但**串口协议没有暴露蓝、青、紫、白命令**，现有程序也只使用三色。
2. **单向通信**：无法读取设备当前状态、固件版本或错误码；设备是否执行成功只能靠肉眼。
3. **无应答/重传**：写失败（串口断开）由主机侧异常捕获，重连后重放最后一条命令。
4. **行结束符敏感**：必须 `\n`，`\r\n` 是否被接受未验证（固件未见 CR 处理逻辑）。

## 9. 待验证项

| 项 | 验证方法 |

| `\r\n` 结尾是否兼容 | 发送 `"RED_ON\r\n"` 观察是否触发 |
